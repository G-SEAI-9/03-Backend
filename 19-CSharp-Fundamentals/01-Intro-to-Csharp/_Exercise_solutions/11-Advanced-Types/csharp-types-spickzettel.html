Was macht welches Keyword?

struct vs. class
Legt den Speicherort fest: Value Type (Stack, Kopie) oder Reference Type (Heap, Adresse).
record
Komfortpaket vom Compiler: Kurzsyntax, Werte-==, with-Kopie und lesbares ToString().
readonly
Sperrt alle Felder – der Wert ist unveränderbar. Ein record ist das schon standardmäßig, ein record struct erst mit readonly davor.

Die 3 Stufen bei struct

  1. struct

    Value Type (Stack), veränderbar, kein == – nur .Equals().

  2. record struct

    Dazu: Kurzsyntax, Werte-==, with und lesbares ToString() – aber noch veränderbar.

  3. readonly record struct Standard für kleine Werte

    Dazu: unveränderbar – readonly sperrt alle Felder.

3 Begriffe kurz erklärt

Stack vs. Heap

Was passiert bei var b = a;?

Stack (Value Type)

Der Wert liegt direkt in der Variable. b = a macht eine echte Kopie. 

var b = a;
// a und b sind unabhängig

Heap (Reference Type)

Das Objekt liegt im Heap, die Variable hält nur die Adresse. b = a teilt dasselbe Objekt. 

var b = a; b.Add(item);
// ändert auch a

Vergleich mit ==

Werte oder Speicheradresse?

Werte-== (Value Equality)

Vergleicht den Inhalt, also die Felder (record, record struct). 

new Point(1, 2) == new Point(1, 2)
// → true (gleicher Inhalt)

Adress-== (Reference Equality)

Prüft nur, ob beide auf dasselbe Objekt zeigen (class). 

new User("Ada") == new User("Ada")
// → false (zwei getrennte Objekte)

Lesbares ToString()

Was gibt Console.WriteLine(x) aus?

Mit record oder override

Der Compiler gibt alle Properties lesbar aus. Per override ToString() frei anpassbar. 

Point { X = 1, Y = 2 }
// alle Properties mit Wert

Normale class / struct

Das Standard-ToString() von object gibt nur den Typnamen aus – ohne Werte. 

MyApp.Models.User
// nur Namespace + Typname

Faustregel: Im Zweifel mit class (State & Logik) oder record (reine Daten) anfangen. readonly record struct nur für winzige, unveränderbare Werte (2–⁠3 Felder).

Wie liest man Func & Action?

Func<Eingabe..., Rückgabe>
Alle Typen vorne sind Eingaben, der letzte Typ ist immer der Rückgabewert.
  • Func<string, int> → string rein, int raus
  • Func<decimal, decimal> → Zahl rein, Zahl raus
  • Func<T, bool> → Predicate (Ja/Nein-Filter)
Action<Eingabe...>
Alle Typen sind Eingaben, zurück kommt nichts (void).
  • Action → nichts rein, nichts raus
  • Action<string> → string rein, void
Brücke aus JavaScript / TypeScript
Dieselbe Idee wie Callbacks in .filter(), .map() oder onClick – nur vom Compiler typgeprüft: Func<int, bool> entspricht (n: number) => boolean.

Wie übergebe ich eine Methode?

Lambda x => ... kurze Regel
Anonyme Methode direkt an der Stelle (wie Arrow Functions in JS). Lässt sich auch in einer Variable speichern und wiederverwenden.
Method Group Name ohne ()
Gibt es schon eine passende Methode, reicht ihr Name – ohne Lambda-Hülle drumherum (Console.WriteLine, list.Add).
Warum das überhaupt?
Eine Methode oder Klasse muss nicht alles fest einbauen – das konkrete Verhalten (Filter, Preisregel, Logger) kommt erst beim Aufruf von außen rein.

3 Unterschiede kurz erklärt

Func vs. Action

Kommt ein Wert zurück?

Func (mit Rückgabe)

Berechnet oder prüft etwas und gibt ein Ergebnis zurück.

Func<decimal, decimal> discount = p => p * 0.9m;
// decimal rein → decimal raus

Action (ohne Rückgabe)

Führt eine Aktion aus (Loggen, Speichern) und gibt nichts (void) zurück. 

Action<string> log = msg => Console.WriteLine(msg);
// string rein → void

Lambda vs. Method Group

Neu schreiben oder bestehende nutzen?

Lambda

Kurze Regel direkt vor Ort schreiben – Typen leitet der Compiler automatisch her. 

Func<int, bool> isPositive = n => n > 0;
// kurz, anonym, direkt lesbar

Method Group

Passt eine vorhandene Methode exakt zur Signatur, reicht ihr bloßer Name.

Action<string> collect = list.Add;
// kürzer als: msg => list.Add(msg)

Übergeben vs. Aufrufen

Mit oder ohne ()?

Ohne () – übergeben

Die Methode selbst wird weitergereicht und erst beim Empfänger ausgeführt. 

Run(Console.WriteLine);
// Methode wird als Argument übergeben

Mit () – sofort aufrufen

Führt die Methode sofort aus und übergibt nur ihr Ergebnis (bei void: Compilerfehler). 

Run(Console.WriteLine());
// Fehler: ruft sofort auf statt weiterzugeben

Faustregel: Im Alltag reichen fast immer Func (mit Rückgabe) und Action (ohne Rückgabe) – ein eigenes delegate braucht man nur selten. Kurze Regel → Lambda, passende Methode schon da → Method Group ohne ().

Die 4 Bausteine des .NET-Event-Patterns

Die vier Bausteine des .NET-Event-Patterns: EventArgs, EventHandler, Auslöser und Handler
Baustein Rolle (Bild) Syntax Regel
EventArgs Briefumschlag Trägt die Daten zum Ereignis (oder leer: EventArgs.Empty) sealed class ...EventArgs : EventArgs Properties nur { get; } Nur lesen unveränderbar für alle
event EventHandler<T>? Abo-Liste Hält alle angemeldeten Methoden (≈ Action<object?, T>) public event EventHandler<T>? Changed; ?, da ohne Abos null Geschützt außen nur += / -=
On<Name>(e) Auslöse-Knopf Ruft alle Abonnenten im Publisher sicher auf Changed?.Invoke(this, e); in protected virtual void OnChanged(T e) Nur innen ?. verhindert Crash
Handler Subscriber-Reaktion Läuft automatisch, sobald das Event ausgelöst wird void Handle(object? sender, T e) publisher.Changed += Handle; Entkoppelt Publisher kennt ihn nicht

Ablauf: Wer ruft wann was auf?

  1. Anmelden mit +=

    Subscriber hängt seine Methode in die Abo-Liste ein. Noch wird nichts ausgeführt.

  2. Etwas passiert im Publisher

    Eine normale Methode läuft, packt die Infos in ein new ...EventArgs(...) und ruft On<Name>(e).

  3. Auslösen per ?.Invoke(this, e)

    ?. prüft, ob Abonnenten da sind; this wird als sender und e als Briefumschlag übergeben.

  4. Alle Handler laufen los

    Jede angemeldete Methode läuft der Reihe nach automatisch mit (sender, e) – egal wie viele es sind.

Wichtige Regeln & typische Fallen

event schützt die Abo-Liste
Von außen sind nur += und -= erlaubt – niemand kann das Event fremdauslösen oder alle Abos mit = null löschen.
Immer ?.Invoke nutzen
Ohne Subscriber ist das Event null. Ein direkter Aufruf ohne ?. wirft eine NullReferenceException.
EventArgs ist eine class (kein record)
In C# kann ein record nicht von der Klasse EventArgs erben (Compilerfehler CS8864) – daher sealed class mit { get; }-Properties.
Wofür steht sender?
Hört derselbe Handler auf mehrere Publisher, verrät sender (per sender is Typ x), wer gerade gesendet hat.

3 Unterschiede kurz erklärt

Publisher vs. Subscriber

Wer kennt wen?

Publisher (Sender)

Hält die Abo-Liste (event) und löst aus – kennt keinen Subscriber (Loose Coupling). 

public event EventHandler<T>? Updated;
protected virtual void OnUpdated(T e)
    => Updated?.Invoke(this, e);

Subscriber (Empfänger)

Kennt den Publisher, meldet sich mit += an und reagiert beim Auslösen. 

source.Updated += HandleUpdate;
void HandleUpdate(object? sender, T e)
{ /* Reaktion */ }

Anmelden vs. Auslösen

Wann läuft der Code?

Anmelden (+=)

Trägt die Methode nur in die Liste ein – wie addEventListener im Browser. 

source.Updated += logger.Log;
// merkt sich Log – läuft noch nicht

Auslösen (?.Invoke)

Erst wenn der Publisher auslöst, laufen alle gemerkten Methoden der Reihe nach los. 

Updated?.Invoke(this, new UpdatedEventArgs(val));
// ruft alle Abonnenten nacheinander auf

Abmelden mit -=

Richtig vs. Lambda-Falle

Dieselbe Methoden-Referenz

Method Group oder gespeicherte Variable – -= findet exakt denselben Eintrag und entfernt ihn. 

source.Updated += logger.Log;
source.Updated -= logger.Log; // abgemeldet

Neue Inline-Lambda

Zwei identisch geschriebene Lambdas sind verschiedene Objekte – -= lässt das Abo einfach weiterlaufen. 

source.Updated += (s, e) => Console.WriteLine(e);
source.Updated -= (s, e) => Console.WriteLine(e);
// wirkungslos (anderes Lambda-Objekt!)

Faustregel: Func / Action als Parameter nutzen, wenn der Aufrufer die Reaktion direkt mitgibt – event EventHandler<T> nutzen, wenn beliebig viele unbekannte Stellen später reagieren sollen. Immer per ?.Invoke(this, e) auslösen.
